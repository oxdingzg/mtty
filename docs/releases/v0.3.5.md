# mtty v0.3.5

[简体中文](v0.3.5.zh-CN.md)

## An image-only paste reaches the pane on Windows

Copying a screenshot and pressing Ctrl+V in a Windows pane did nothing. mtty
already read the clipboard image and wrote it to `MTTY_CLIPBOARD_FILE`, then
signalled the paste with an empty bracketed paste. ConPTY drops that empty
`ESC[200~ ESC[201~` pair before the application sees it, so the pane received
no input at all and the image was ignored.

On Windows the host now sends the legacy Ctrl+V byte (`0x16`) for an image-only
paste. Applications already treat Ctrl+V as "read the clipboard", and miao's
reader prefers the host-written file, so the image lands as an attachment.
Text pastes, and the empty bracketed paste Unix terminals already honor, are
unchanged.

## Maintenance and verification

Cross-platform CI covers Linux, macOS and Windows, along with rendering and
release-mode performance gates.

Packages: macOS ARM64 and Intel ZIP bundles; Linux x86-64 tar.gz, AppImage and
deb; Windows x86-64 ZIP and MSI. Existing macOS signing and notarization remain
in place.
