# mtty v0.2.8

[简体中文](v0.2.8.zh-CN.md)

## macOS releases are signed and notarized

Until now the macOS app was shipped ad-hoc signed, so Gatekeeper blocked every
download on a machine that had not approved the previous build: the app would
not open until "Allow Anyway" was pressed under Privacy & Security. Release
builds are now signed with the Developer ID identity (hardened runtime) and
notarized through the App Store Connect API before publication, and the
stapled ticket travels inside the ZIP. A fresh download opens like any app
from the internet — no security-settings detour. (#162)

The CI release pipeline imports the signing certificate into a job-local
keychain and submits each macOS archive to notarization with `--wait`, failing
the release rather than shipping an unsigned build if notarization is
rejected.

## Performance baseline refresh

The CI performance baseline was refreshed from the latest schedule run, so
the comparative gates measure against current hardware results instead of an
older machine's numbers. (#154)

## Verification and packages

Full cross-platform CI, rendering and performance gates passed before each
change merged.

Packages: macOS ARM64 and Intel ZIP bundles; Linux x86-64 tar.gz, AppImage and
deb; Windows x86-64 ZIP and MSI. Publication verifies package contents, update
manifest checksums and detached signatures.

The v0.2.7 context-menu and dev-bundle signing fixes and earlier fixes remain
included.
