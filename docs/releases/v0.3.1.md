# mtty v0.3.1

[简体中文](v0.3.1.zh-CN.md)

## Sign in to your Hub account from the title bar

When miao is installed, an account chip now sits next to the window controls:
`Sign In` before an account is attached, and `Account` once the active pane's
miao Runtime reports a connected Hub account. Clicking it opens a small dialog
for the Hub URL, email, password and an optional machine name. (#212)

Sign-in goes through miao's private-pipe bridge for the active pane's owned
Runtime, so miao keeps the account credentials and the Hub binding; mtty only
displays live state and forwards the request. Attached, missing or malformed
pane context is rejected before any credential moves, and closing the dialog
cancels an in-flight request. Terminal users get the same account through
`miao remote login/status/logout`, shipped with the next miao release.

## Optional by design

Signing in stays optional: the chip is hidden while miao is not installed,
remote control keeps working without an account, and mtty still never calls a
model itself. PRODUCT.md and the READMEs now state the non-goal as "no
mandatory sign-in" instead of "no accounts".

## Maintenance and verification

The scheduled CI performance baseline is refreshed; absolute performance
budgets are unchanged. Cross-platform CI covers Linux, macOS and Windows, along
with rendering and release-mode performance gates.

Packages: macOS ARM64 and Intel ZIP bundles; Linux x86-64 tar.gz, AppImage and
deb; Windows x86-64 ZIP and MSI. The release pipeline checks package contents,
update-manifest checksums and detached signatures. Existing macOS signing and
notarization remain in place.
